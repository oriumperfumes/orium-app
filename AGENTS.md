- Keep one debounced catalog-search value shared by the inline bar, sticky bar, preview, intent, URL, and result grid; this prevents stale or contradictory results.
- Keep automatic global route preloading disabled and use explicit stable link preloads only; this avoids route-match races in the Admin.
- Motion: use only `--motion-fast/standard/emphasis` + `--ease-orium` from styles.css; one easing app-wide for consistency.
- QueryClient defaults: staleTime 30s, no refetch on focus; screens with critical freshness set their own staleTime.
- Product photos: resize/encode in the Admin browser (Worker has no image libs); `product_image_cache` + trigger `products_zz_optimized_image` swap supplier URLs for Orium WebP variants; render via `imgVariant`/`imgSrcSet`.
- All app AI calls go through src/lib/ai/engine.server.ts (OpenAI, OPENAI_API_KEY, usage logged to ai_usage, budgets from ai_settings); never call the Lovable AI gateway or another provider directly — keeps cost control and one failure policy.
- Copilot price answers/quotes come only from src/lib/copilot/pricing-tools.server.ts, which reuses priceCart (the cart/checkout engine); never put prices in prompts or a separate AI price table — keeps one source of truth.
- AI model choice per task goes through routeTask() + prepare(profile) in engine.server.ts (profiles: economy/copilot/advanced/voice/vision, models stored in ai_settings); features never hardcode a model — lets the owner swap models in the AI Center.
- Orders link to CRM by catalog_orders.crm_customer_id (trigger crm_link_order_customer fills it by phone only when empty); order name/phone are a per-order snapshot and never overwrite the linked crm_customers row — keeps one customer record and stable history.
- Supplier Hub: priority/permission/logistics flags live on `suppliers`; `recompute_product_pricing` (pricing/availability) and `purchase/compare.server.ts` (Restock) must honor them plus `supplier_product_preferences`; suppliers with `creates_catalog_products=false` never create public products and only auto-link via `strictSameProduct` — keeps reference suppliers from changing prices or polluting the catalog.
- Any Kyte store goes through `src/lib/suppliers/kyte-connector.server.ts` (adapter `kyte-connector`, store id in `adapter_config.aid`), and supplier URLs pass `url-guard.server.ts` — one reusable reader, SSRF-safe.
- Public-catalog permission is per supplier offer: `suppliers.catalog_mode` + `supplier_offer_catalog` (allow/deny, never written by sync) gate only `supplier_available` in `recompute_product_pricing`; pricing, comparison and purchasing ignore it — blocking an offer never hides a product another source can supply.
- Supply freight (supplier → Orium) lives in `src/lib/suppliers/freight(.server).ts`: one quote per shipment via `superfreteQuote` with the supplier's own origin CEP, allocated by units/value/weight; never reuse the customer-shipping origin and never invent package data or freight values.
- Storefront overlays/sheets (sacola, conta, filtros, folhas de compra, kit, lead) load on demand via `lazyUI` + `MountWhen` from src/lib/lazy-ui.tsx and prefetch on idle; import light pieces (e.g. `account-shared`, `filters-options`) statically, never the heavy module — keeps them out of the first load.
- Storefront layout: page frame is the `shell` utility (max `--shell-max`, gutters from `--page-gutter`: 20/32/40/48px); product lists use `product-grid` (2/3/4/5 cols); from `lg` (64rem) navigation lives in SiteHeader and the bottom bar hides; Sacola/Conta become a right panel and store sheets float (admin excluded via `html.is-admin`) — keeps tablet/desktop consistent.
- Overlays close on the phone back gesture via `useBackToClose` (built into ui/drawer, ui/dialog, ui/sheet; used by CartDrawer, AccountScreen, OfferPopup). When navigating from inside an overlay, call `navigatingFromLayer()` and navigate with `replace: true` — otherwise the closing overlay can undo the navigation.
- Admin look: tokens/overrides live in the "ADMIN — mesma linguagem da loja" block of styles.css (scoped to `.admin-theme`/`body.admin-mode`): #101010 page, #0A0A0A bars, #1A1A1A cards, #1F1F1F controls, selected = white, gold only as accent, no gradients/blur/glow. Desktop nav = pill top bar (`AdminTopBar`, Ctrl K palette); Início/Pedidos use `.dash-card`/`.dash-hero` cards and `components/orium/admin/orders/*` (board, panel, composer).
- Orders control: Pedidos tabs Hoje (alerts) · Quadro · Lista · Compras; supplier purchases read/write only via `src/lib/orders-control.functions.ts` (status transitions guarded server-side: a comprar → pedido feito → recebido, never twice); `catalog_orders.payment_due_date` and `restock_items.planned_purchase_date/purchased_at/received_at` drive the alerts; manual/edited prices travel as `unitPrice` and are never overwritten by priceCart.
- Supplier orders: every "Mandei"/"Já pedi por fora" creates a `supplier_orders` + `supplier_order_items` snapshot (markPurchased); arrival is checked item by item (checkSupplierOrder: ok/faltou/quebrado/errado, esperar or repedir) and open issues resolved via resolveSupplierIssue — never edit restock_items status directly from the UI for these flows.
- Order phase (Esperando pagamento → Falta pedir no fornecedor → Vindo do fornecedor → Pronto para entregar → Entregue) comes only from `orders/phase.tsx` (`phaseOf`, built on `journeyOf` + the ["purchase-board"] query); cards, panel and the Painel table all read it — one rule, never recomputed per screen. ## Preço sob consulta (fornecedor só de consulta)
- `products.price_on_request = true` → o site mostra "Sob consulta" e o botão "Consultar no WhatsApp" (Orium) no lugar do preço; o produto nunca entra na Sacola.
- As listas públicas vêm de RPCs com colunas fixas, então os cards usam `useConsultIds()` / `isOnRequest()` de `src/lib/price-on-request.ts`.
- Fornecedor "referência" sem preço/compra (ex.: Rasha, adapter `loja-integrada`) mostra no catálogo o botão "Adicionar ao site (sob consulta)", que abre o ManualProductSheet já preenchido.
- O preço do site desses fornecedores é de atacado: nunca usar para preço de venda. `calculateProductPricing` ignora ofertas de fornecedor com `use_for_pricing=false`, exceto quando o perfume não tem outro fornecedor com preço.
- O catálogo de consulta nunca vai ao site. A vitrine do "Novo pedido" junta tudo num só lugar via `composerSupply` (`src/lib/composer-supply.functions.ts`): `byProduct` = ofertas de todos os fornecedores do nosso perfume (inclusive de consulta com o mesmo nome, por `perfumeKey`); `extras` = perfumes que só existem nos fornecedores de consulta, mostrados como card normal com selo "Fora do site". Ao entrar no pedido, `productFromConsultOffer` cria UMA vez o produto interno (`catalog_eligibility_reason = "interno-consulta"` → `public_visible=false`) e liga as ofertas.
- Cada frasco no pedido tem "Comprar de" (`SupplierPick`); a escolha vai como `supplierProductId` e grava `catalog_order_items.supplier_chosen=true`, que a reposição (`orders-restock.server.ts`) respeita no lugar de `product_costs.best_supplier_id`.
- Rasha (Loja Integrada) bloqueia leitura automática da página 2 em diante (HTTP 403): o adapter fica com a 1ª página (lançamentos) e o catálogo completo foi carregado do mapa do site (`/sitemap/product-*.xml`, só nome/link, `offer_source="sitemap"`).
- Preço de atacado combinado na mão: `WholesaleToggle` (Novo pedido e Editar pedido) liga o atacado mesmo com menos de 6 frascos; vai como `wholesale` para `createManualOrder`/`editOrder` e fica em `catalog_orders.pricing_tier = "atacado"` (o painel do pedido mostra "Preço: Atacado").
- Fornecedores de consulta são completados sozinhos pelo agendamento `consult-enrich` (hook `/api/public/hooks/consult-enrich`: `{"step":"match"}` às :35 roda `enrichConsultOffers`. A etapa `{"step":"brand"}` (página da marca na Fragrantica) existe mas está sem agendamento: a Fragrantica recusa leituras automáticas desde set/2026): liga ao nosso perfume por `perfumeKey`/`keyMatch` (`src/lib/perfume-key.ts`, mesmo volume e marca) e preenche a foto que falta com o mesmo perfume em outro fornecedor ou pelo `fragrantica_index` (foto oficial `fimgs.net/mdimg/perfume/375x500.<id>.jpg`). Sem custo: nenhuma API paga; só lê páginas de marca da Fragrantica pela rotina já existente (`brandCandidates`, cache de 7 dias, 4 marcas por rodada).
- Tocar no perfume do Novo pedido abre a telinha `SupplySheet` (kit.tsx): "Já tenho na loja", cada fornecedor com foto/custo/disponível, procurar em outro fornecedor e decant; a escolha vira `supplierProductId` do item. No item do pedido, "Comprar de" continua para trocar depois; "Outro"/"Escolher fornecedor" procura em todos os fornecedores (`searchSupplierOffers`) e liga a oferta solta ao nosso perfume (`linkOfferToProduct`).
- Remover fornecedor (Gerenciar › Configurações › "Remover fornecedor"): `setSupplierRemoved` desliga o fornecedor (active=false, priority inactive, sem sincronizar) e as ofertas dele; nada é apagado. Fornecedores › "Removidos" traz de volta.
- Pagamento por perfume: `catalog_order_items.paid`. `PayAmount` (controls.tsx) mostra "Pagou quais perfumes?" quando há 2+ itens; marcar soma o valor dos itens (todos = total com frete). Grava via `setOrderPayment({ paidItemIds })` e `createManualOrder` (`items[].paid`); o painel do pedido mostra "Pago/Falta pagar" por item quando o pagamento é parcial.
- Equipe (Configurações › Equipe, `src/lib/team.functions.ts` + `TeamSettings.tsx`): lista donos/admins (`user_roles` owner/admin); só Dono adiciona (convite por e-mail se não houver conta), troca Dono/Admin ou tira acesso; nunca fica sem dono e ninguém tira o próprio acesso.
- Identificação dos pedidos (`orders/ident.tsx`): `OrderPhotos` monta a foto com todos os perfumes (2 = metade/metade, 3 = 1+2, 4+ = grade com +N), `itemsText` mostra "2× Nome · Nome", `TierBadge` mostra "Atacado" e `ExpandButton`/`ItemsExpand` abrem os perfumes embaixo da linha sem abrir o pedido. Usados no Painel, Quadro/Urgente e Lista.
- Movimento do Admin: peças em `src/components/orium/admin/motion.tsx` (`Collapse` abre/fecha com altura animada e conteúdo em cascata via `.ui-stagger`; `PillTrack` pílula que desliza até a aba com `aria-pressed`; `AnimatedNumber` conta até o valor novo; `ViewSwap` troca de tela suave) + classes `.ui-*` no fim de styles.css, todas com `--ease-orium` e desligadas em "reduzir movimento". `body.admin-mode .press` junta a mola do toque com a troca de cor (antes `transition-colors` apagava a mola). Sheets fecham com `.ui-leaving` (fundo some, painel desce) antes de desmontar.
- Urgência da entrega: `WhenPill` (orders/ident.tsx) — hoje = pílula dourada com ponto que "respira" (`.ui-beacon`) e contagem até 6 h antes ("em 40 min"); faltando 1 h, passou da hora ou atrasado = pílula coral; amanhã em diante = texto simples. Um relógio só (30 s) para a tela toda. Nada de faixas laterais coloridas nos cartões.
- Menu do pedido (`orders/OrderMenu.tsx`): um só menu para o "⋯" do painel (`OrderMenuButton`), botão direito e "segurar" o dedo em qualquer linha com `data-order-id` dentro de `OrderMenuZone` (Shift + botão direito = menu do navegador). As opções vêm de `menuOf` em admin.pedidos: atalhos (Abrir/Editar/WhatsApp/Copiar), o próximo passo da fase em destaque, "Recebi o pagamento", Duplicar, e Cancelar/Lixeira separados. Nada de "Marcar como…" ou "Reposição" — a etapa vem de `phaseOf`.
- Compras › Enviar pedido (`SendCenter` em PurchasesView): a janela nasce do botão clicado (FLIP com `morphFrames`, cor do botão → #121212) e volta para ele ao fechar; "Mandei" mostra "Pedido feito!" com check desenhado, aviãozinho voando (`flyPlane`) e confete, o fornecedor fecha (Collapse) com check verde e o próximo abre; barra por fornecedor (`.send-seg`); fim com anel + check desenhados. Campos de texto do Admin sem anel dourado no foco: o fundo clareia (`focus:bg-[#2A2A2A]`).
- Velocidade do catálogo público: `search_catalog` calcula os nomes do "hype" uma vez (CTE `hn` materializada) e a pontuação de texto uma vez (`scored` materializada) — ≈300 → ≈90 ms; ao mexer nela, conferir com EXCEPT ALL contra a versão anterior. A 1ª página da Home sai já no `<head>` (`src/lib/catalog-prefetch.ts`, só variáveis VITE_ para o head ser igual no servidor e no navegador) e a consulta usa `takeCatalogPrefetch`; mudar os argumentos padrão da Home = mudar `CATALOG_FIRST_ARGS`. Fotos (`/api/public/produto-foto`, `negociacao-foto`) ficam no cache da borda (`caches.default`) e o `sw.js` guarda `/assets/*` e fotos (cache primeiro, nome único; dados nunca). "Ao vivo" (`LiveProvider`) só monta depois do load (`AfterLoad` em __root).
- Versões do mesmo perfume NUNCA são duplicadas: concentração diferente (EDT ≠ EDP ≠ Parfum ≠ Extrait) ou ml diferente = outro produto. `sameVariant`/`variantOf` (src/lib/perfume-key.ts) guardam isso na ligação dos fornecedores de consulta, nas fotos emprestadas e na vitrine do Novo pedido; oferta sem ml nem concentração não é ligada quando temos mais de uma versão (ambíguo). "Limited Edition" sozinho não separa. Antes de ocultar "duplicados" no banco, comparar marca + nome + concentração + ml.
- `products`: `anon` e `authenticated` leem só as 39 colunas públicas (as 38 de antes + `price_on_request`) (grant por coluna) e `authenticated` não escreve na tabela; colunas internas (`manual_cost`, `local_stock`, `ready_to_deliver`, chaves de identidade...) só por server functions que confirmam `is_staff` e usam o cliente de serviço (`src/lib/product-internal.functions.ts`, `getAdminProductRow`); pronta entrega pública vem de `public_ready_to_deliver_ids()` — nunca `select("*")` nem filtro por coluna interna no navegador.
